# 经济系统

## 一句话

宠物在你离开时"看家"赚硬币，硬币用来买食物。照顾得好，赚得多。

## 货币

**只有一种：硬币（coin）。**

不做双货币。`My Tamagotchi Forever` 的教训是玩家会把次要货币视作无用
（"Gems... are almost worthless"），而维护两套定价、两套 UI 的成本却是双倍。

存档独立于宠物状态：

```swift
struct PetWallet: Codable {
    var coins: Int
    /// 上次结算时间。离线收益与上线奖励都以它为基准。
    var lastCollectedAt: Date
    /// 小鱼干 buff 到期时间。nil = 无 buff。
    var boostUntil: Date?
    /// 累计赚取（成就用，只增不减）
    var totalEarned: Int
    /// 今日已从看家收益赚到的额度。必须落盘，否则反复开关 app 可绕过上限。
    var todayEarned: Int
    /// todayEarned 对应的日期，用于判断跨日
    var lastEarnDate: Date
}
```

**为什么钱包不塞进 `PetState`**：换宠物不该清空钱包。
两者生命周期不同，分开存也让 `PetState` 的解码兼容逻辑不至于更复杂。

## 收益来源一：离线看家（每日额度制）

```
硬币 = min(今日剩余额度, 每日额度 × 达成率 × buff倍率)
```

| 参数 | 值 | 理由 |
|---|---|---|
| 每日额度 | 幼170 / 成长195 / 成年225 / 老205 | 养大了赚得多 |
| 达成率 | 0.05 ~ 0.35 | 核心正循环，见下 |
| buff 倍率 | 1.0 或 1.6 | 小鱼干生效期内抬高达成率 |
| 单次领取上限 | **无** | 曾有，会遮蔽达成率，见 04 的第 7 版 |

### 为什么是额度制，而不是按小时累积

旧公式是 `min(离线小时, 10) × 速率 × 状态系数`。问题在于**支出**：
喂食按次固定价，一天喂 n 次就花 n 份钱（线性），
而收入被 10 小时上限压平（常数）。结果是照顾越勤越亏 ——
和「照顾好宠物=赚得多」正好相反。

按 Daniel Cook 的 source/sink 幂次分类，这是 capped source 配
repeatable sink 的典型失配，靠调单价永远调不平。完整分析见
[04-balance.md](04-balance.md#收入与支出的幂次匹配)。

额度制把收入变成明确的常数级，配合「食物按恢复量计价」把支出也变成常数级，
两端幂次对齐，问题从结构上消失。

### 达成率

```
达成率 = 0.05 + 0.30 × (0.40×饱食 + 0.60×心情)²        // 0.05 ~ 0.35
```

#### 为什么用离线期间的平均值，而不是离开那一刻

用「离开那一刻的状态」会被钻空子：喂饱后立刻关掉，挂 12 小时回来照样拿满，
而宠物实际饿了 4 小时。

衰减是线性的，所以平均值用梯形法就是精确解：

```
平均值 = 1 - 离线时长 / (2 × 周期)        // 离线 ≤ 周期
       = (周期 × 0.5) / 离线时长          // 离线 > 周期，衰减到 0 后一直是 0
```

#### 为什么用平方

线性版本（`0.35 + 0.65×blend`）只能在勤快与放养之间拉开 2.2 倍差距，
压不住喂食支出的增长。平方后差约 4 倍：

| 状态 | blend | 达成率 |
|---|---|---|
| 都满 | 1.00 | 0.35 |
| 良好 | 0.85 | 0.27 |
| 一般 | 0.60 | 0.16 |
| 较差 | 0.35 | 0.09 |
| 都空 | 0.00 | 0.05 |

#### 为什么上界是 0.35 而不是 1.0

**让一次结算领不满额度。** 若上界是 1.0，开一次就能拿满，
「开 1 次」和「开 5 次」收入相同，激励结构失效。

0.35 意味着约 3 次结算才领满，正好落在目标节奏（4-5 次/天）之下 ——
所以「多开一次」在到达峰值前始终有收益。

#### 心情权重高于饱食

`0.60 vs 0.40`。情绪价值是宠物 app 的核心，而且饱食有免费剩饭保底，
惩罚不该过重。心情从满到空，达成率降到约 30%。

#### 清洁不参与

72 小时周期让清洁长期接近 1.0 —— 离线 24 小时时它还有 0.83，
而饱食只剩 0.17。放进公式只会稀释另两维，让「饿着」这件事看起来不严重。

它仍然是照料内容：状态条、脏了的台词、洗澡成就（`clean_20` / `clean_100`）
全部保留，只是不折算成钱。

### 额度封顶后会怎样

领满当日额度后，`OfflineCareReward` 返回 nil，不再产生看家收益。
上线奖励和成就**不占额度**，所以仍然照发。

⚠️ 目前没有任何 UI 提示「今日额度已满」，玩家可能困惑
「怎么这次开没赚钱」。这是已知的体验缺口。

### 防刷币

`todayEarned` 与 `lastEarnDate` **落盘在 wallet.json**，
跨日由 `PetWallet.recordEarning` 自动重置。

必须落盘 —— 只在内存里算的话，反复开关 app 每次都能拿满额度。
这是额度制最主要的刷币面，由
`EconomyTests.testDailyCapCannotBeFarmedByRelaunching` 守着。


## 收益来源二：上线奖励

```
每次打开 +10 枚，要求距上次结算 ≥ 5 小时
```

5 小时的间隔限制是为了防无脑开关刷币。配合饱食周期（成年 8 小时），
自然形成「一天 3-4 次」的节奏上限。

**不占每日额度** —— 否则「领了上线奖励反而少赚看家钱」，语义荒谬。
由 `RewardRule.countsTowardDailyCap` 区分，只有看家收益返回 true。

奖励只给 10 枚是刻意的：**它的作用是"每次回来都有一点点收获"的心理反馈**，
而非收入主力。收入主力是看家收益。

## 结算的呈现

**走现有的台词气泡系统**，宠物自己说出来：

> "我帮你看家赚了 41 枚！"

复用 `PetScene.showSpeech()`，零新 UI，而且强化了宠物的存在感——
钱是"它挣的"，不是系统发的。

低于 10 枚不说话（避免刚关掉又打开就弹）。

## 不做防作弊

单机游戏改系统时间就能刷钱，**防不住**：
- 没有服务器，拿不到可信时间
- 没有内购，刷钱不损害任何人（包括开发者）
- 唯一受害者是作弊者自己的游戏体验

每日额度和 5 小时间隔**不是防作弊措施**，是节奏设计。

但 `todayEarned` 落盘是必要的 —— 它防的不是改时间，
而是「反复开关 app」这种无需任何工具的意外刷币路径。

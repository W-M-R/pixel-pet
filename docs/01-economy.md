# 经济系统

## 一句话

宠物在你离开时"看家"赚硬币，硬币用来买食物。照顾得好，赚得多。

## 货币

**只有一种：硬币（coin）。**

不做双货币。`My Tamagotchi Forever` 的教训是玩家会把次要货币视作无用
（"Gems... are almost worthless"），而维护两套定价、两套 UI 的成本却是双倍。

存档独立于宠物状态：

```swift
struct PetWallet: Codable {
    var coins: Int
    /// 上次结算时间。离线收益与上线奖励都以它为基准。
    var lastCollectedAt: Date
    /// 小鱼干 buff 到期时间。nil = 无 buff。
    var boostUntil: Date?
    /// 累计赚取（成就用，只增不减）
    var totalEarned: Int
}
```

**为什么钱包不塞进 `PetState`**：换宠物不该清空钱包。
两者生命周期不同，分开存也让 `PetState` 的解码兼容逻辑不至于更复杂。

## 收益来源一：离线看家

```
硬币 = min(离线小时数, 10) × 1.0 × 状态系数 × buff倍率
```

| 参数 | 值 | 理由 |
|---|---|---|
| 基础速率 | 1.0 枚/小时 | 见 [04-balance.md](04-balance.md) 的调参过程 |
| 时长上限 | 10 小时 | 防"放一个月回来暴富"导致后续没动力 |
| 状态系数 | 0.4 ~ 1.5 | 核心正循环，见下 |
| buff 倍率 | 1.0 或 1.3 | 小鱼干生效期内 1.3 |

### 状态系数：按离线期间的平均状态算

这是整个设计里最关键的一处。

**不能用"离开那一刻的状态"** —— 那样用户可以喂饱后立刻关掉，
挂 12 小时回来照样拿满系数，而宠物实际饿了 4 小时。

正解是算**离线期间的平均值**。饱食是线性衰减，所以梯形法就是精确解：

```
平均饱食 = (离开时饱食 + 回来时饱食) / 2      // 未衰减到 0 时
         = (周期 × 0.5) / 离线时长            // 已衰减到 0 时
```

实际数值（饱食周期 8 小时）：

| 离线时长 | 平均饱食 | 状态系数 |
|---|---|---|
| 5h | 0.69 | 1.16 |
| 6h | 0.62 | 1.08 |
| 8h | 0.50 | 0.95 |
| 10h | 0.40 | 0.84 |
| 12h | 0.33 | 0.77 |
| 24h | 0.17 | 0.59 |

系数公式：`0.4 + 平均状态 × 1.1`

这个设计的好处是**"长时间不管"会自动惩罚，不需要额外规则**。
离线 24 小时虽然时长撞上限拿 10 小时，但系数只有 0.59，收益是 5.9 枚而非 10 枚。

> 实现注意：平均状态应综合饱食/心情/清洁三条线，而非只看饱食。
> 三者周期不同（8h / 18h / 72h），所以清洁的权重天然更低——这符合直觉，
> 没人指望"三天没洗澡"和"八小时没吃饭"一样严重。

## 收益来源二：上线奖励

```
每次打开 +1 枚，要求距上次结算 ≥ 5 小时
```

5 小时的间隔限制是为了防无脑开关刷币。配合 8 小时的饱食周期，
自然形成"一天 3-4 次"的节奏上限。

奖励只给 1 枚是刻意的：**它的作用是"每次回来都有一点点收获"的心理反馈**，
而非收入主力。收入主力是看家收益。

## 结算的呈现

**走现有的台词气泡系统**，宠物自己说出来：

> "我帮你看家赚了 12 枚！"

复用 `PetScene.showSpeech()`，零新 UI，而且强化了宠物的存在感——
钱是"它挣的"，不是系统发的。

低于 1 枚不说话（避免刚关掉又打开就弹）。

## 不做防作弊

单机游戏改系统时间就能刷钱，**防不住**：
- 没有服务器，拿不到可信时间
- 没有内购，刷钱不损害任何人（包括开发者）
- 唯一受害者是作弊者自己的游戏体验

10 小时上限和 5 小时间隔**不是防作弊措施**，是节奏设计。

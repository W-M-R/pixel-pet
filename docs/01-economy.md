# 经济系统

## 一句话

宠物在你离开时"看家"赚硬币，硬币用来买食物。照顾得好，赚得多。

## 货币

**只有一种：硬币（coin）。**

不做双货币。`My Tamagotchi Forever` 的教训是玩家会把次要货币视作无用
（"Gems... are almost worthless"），而维护两套定价、两套 UI 的成本却是双倍。

存档独立于宠物状态：

```swift
struct PetWallet: Codable {
    var coins: Int
    /// 上次结算时间。离线收益与上线奖励都以它为基准。
    var lastCollectedAt: Date
    /// 小鱼干 buff 到期时间。nil = 无 buff。
    var boostUntil: Date?
    /// 累计赚取（成就用，只增不减）
    var totalEarned: Int
}
```

**为什么钱包不塞进 `PetState`**：换宠物不该清空钱包。
两者生命周期不同，分开存也让 `PetState` 的解码兼容逻辑不至于更复杂。

## 收益来源一：离线看家

```
硬币 = min(离线小时数, 10) × 0.9 × 状态系数 × buff倍率
```

| 参数 | 值 | 理由 |
|---|---|---|
| 基础速率 | 0.9 枚/小时 | 见 [04-balance.md](04-balance.md) 的调参过程 |
| 时长上限 | 10 小时 | 防"放一个月回来暴富"导致后续没动力 |
| 状态系数 | 0.58 ~ 1.35 | 核心正循环，见下 |
| buff 倍率 | 1.0 或 1.3 | 小鱼干生效期内 1.3 |

### 状态系数：三维乘法

这是整个设计里最关键的一处。

#### 为什么用离线期间的平均值，而不是离开那一刻

用"离开那一刻的状态"会被钻空子：喂饱后立刻关掉，挂 12 小时回来照样拿满系数，
而宠物实际饿了 4 小时。

三条线都是线性衰减，所以平均值用梯形法就是精确解：

```
平均值 = 1 - 离线时长 / (2 × 周期)        // 离线 ≤ 周期
       = (周期 × 0.5) / 离线时长          // 离线 > 周期，衰减到 0 后一直是 0
```

各维度在不同离线时长下的平均值：

| 离线 | 饱食(8h) | 心情(18h) | 清洁(72h) |
|---|---|---|---|
| 5h | 0.69 | 0.86 | 0.97 |
| 8h | 0.50 | 0.78 | 0.94 |
| 12h | 0.33 | 0.67 | 0.92 |
| 24h | 0.17 | 0.38 | 0.83 |
| 48h | 0.08 | 0.19 | 0.67 |

#### 为什么用乘法，不用加权平均

**加权平均会削弱惩罚。** 清洁周期长达 72 小时，离线 24 小时时它还有 0.83，
等权平均会把总分从 0.46 拉到 0.46 以上，掩盖饱食只剩 0.17 的事实。

实测对比（离线 12h）：

| 算法 | 结果 | 问题 |
|---|---|---|
| 只看饱食 | 0.33 | 心情差不扣钱 |
| 等权平均 | 0.64 | 被清洁拉高，惩罚太轻 |
| 纯乘法 | 0.20 | 24h 时只剩 0.05，收益归零，太狠 |
| **压缩后乘法** | **0.69** | ✅ 采用 |

所以采用**压缩区间后再相乘**：每个维度先映射到一个不触底的区间，再乘起来。
这样任一维度差都会扣收益（乘法的特性），但不会因为某维度归零就收益全无。

```
系数因子 = (0.70 + 0.30 × 饱食)      // 区间 [0.70, 1.00]
         × (0.45 + 0.55 × 心情)      // 区间 [0.45, 1.00]  ← 惩罚最重
         × (0.85 + 0.15 × 清洁)      // 区间 [0.85, 1.00]  ← 惩罚最轻

状态系数 = 0.3 + 系数因子 × 1.05      // 最终范围 0.58 ~ 1.35
```

#### 三个维度的权重差异是刻意的

压缩区间的宽度就是权重：区间越宽，该维度对收益的影响越大。

| 维度 | 区间 | 宽度 | 心情差→收益 | 理由 |
|---|---|---|---|---|
| 心情 | [0.45, 1.00] | **0.55** | 最重 | 情绪价值是宠物 app 的核心 |
| 饱食 | [0.70, 1.00] | 0.30 | 中 | 有免费"剩饭"保底，不该惩罚过重 |
| 清洁 | [0.85, 1.00] | 0.15 | 最轻 | 周期 72h，本就是低频维护 |

**心情权重最大**，这直接回答了"心情很差时收入要降低"：

| 心情 | 状态系数 | 10h 收益 | 相对满心情 |
|---|---|---|---|
| 1.0 | 1.31 | 11.8 | 100% |
| 0.8 | 1.20 | 10.8 | 92% |
| 0.6 | 1.09 | 9.8 | 83% |
| 0.4 | 0.98 | 8.8 | 75% |
| 0.2 | 0.87 | 7.8 | 66% |
| 0.0 | 0.75 | 6.8 | **58%** |

（其余维度保持良好：饱食 0.9、清洁 0.95）

心情从满到空，收益降 **42%**。这个幅度足以让玩家在意，
但不会让"忘了陪它玩"变成灭顶之灾。

#### 综合状态的整体影响

| 状态 | 饱食 | 心情 | 清洁 | 系数 | 相对全满 |
|---|---|---|---|---|---|
| 全满 | 1.0 | 1.0 | 1.0 | **1.35** | 100% |
| 良好 | 0.8 | 0.8 | 0.9 | 1.17 | 86% |
| 一般 | 0.5 | 0.5 | 0.8 | 0.93 | 69% |
| 较差 | 0.3 | 0.3 | 0.6 | 0.78 | 58% |
| 很差 | 0.1 | 0.1 | 0.4 | 0.65 | 48% |
| 全空 | 0.0 | 0.0 | 0.0 | **0.58** | **43%** |

全空是全满的 **43%**。摆烂能赚，但明显吃亏——这正是想要的效果：
**惩罚足够被感知，但不会让人玩不下去。**

#### 时长上限与系数的叠加效果

| 离线 | 系数 | 收益 |
|---|---|---|
| 2h | 1.28 | 2.3 |
| 5h | 1.17 | 5.3 |
| 8h | 1.08 | 7.8 |
| 10h | 1.02 | **9.2** ← 峰值 |
| 12h | 0.98 | 8.8 |
| 18h | 0.87 | 7.9 |
| 24h | 0.80 | 7.2 |
| 48h | 0.70 | 6.3 |

收益在 10 小时（时长上限）达到峰值后**开始下降**：时长不再增长，
但状态继续恶化拉低系数。

这是刻意设计——"长时间不管"应该有代价，而且不需要额外的惩罚规则。

## 收益来源二：上线奖励

```
每次打开 +1 枚，要求距上次结算 ≥ 5 小时
```

5 小时的间隔限制是为了防无脑开关刷币。配合 8 小时的饱食周期，
自然形成"一天 3-4 次"的节奏上限。

奖励只给 1 枚是刻意的：**它的作用是"每次回来都有一点点收获"的心理反馈**，
而非收入主力。收入主力是看家收益。

## 结算的呈现

**走现有的台词气泡系统**，宠物自己说出来：

> "我帮你看家赚了 12 枚！"

复用 `PetScene.showSpeech()`，零新 UI，而且强化了宠物的存在感——
钱是"它挣的"，不是系统发的。

低于 1 枚不说话（避免刚关掉又打开就弹）。

## 不做防作弊

单机游戏改系统时间就能刷钱，**防不住**：
- 没有服务器，拿不到可信时间
- 没有内购，刷钱不损害任何人（包括开发者）
- 唯一受害者是作弊者自己的游戏体验

10 小时上限和 5 小时间隔**不是防作弊措施**，是节奏设计。

# 食物系统

## 四档

| 档位 | emoji | 空腹价 | = 饱食部分 + 效果固定价 | 恢复饱食 | 附加 |
|---|---|---|---|---|---|
| 剩饭 | 🥣 | **免费** | — | 30% | — |
| 普通粮 | 🍚 | 35 | 35 + 0 | 70% | — |
| 罐头 | 🥫 | 150 | 50 + **100** | 100% | 心情 +10% |
| 小鱼干 | 🐟 | 250 | 50 + **200** | 100% | 心情 +25%、达成率 ×1.6（24h） |

「空腹价」= 饱食为 0 时的花费。实际花费随饱食度变化，见下。

## 计价公式

```swift
func cost(currentSatiety: Double) -> Int {
    guard !isFree else { return 0 }
    let gained = min(satietyRestore, 1.0 - currentSatiety)   // 实际补上的量
    let satietyPart = Int((gained * 10 * Double(coinsPer10Percent)).rounded())
    return max(minPrice, satietyPart + extraPrice)
}
```

三段各解决一个问题：

| 段 | 作用 | 不这么做会怎样 |
|---|---|---|
| 饱食部分**按量** | 支出饱和成常数级 | 喂得越勤越亏 |
| 附加效果**固定价** | buff 的价钱不随饱食打折 | 快饱时买小鱼干几乎免费却拿满 buff |
| **最低价**兜底 | 满饱时也要花钱 | 零成本反复点喂食刷成就 |

| 当前饱食 | 剩饭 | 普通粮 | 罐头 | 小鱼干 |
|---|---|---|---|---|
| 0% | 0 | 35 | 150 | 250 |
| 30% | 0 | 35 | 135 | 235 |
| 60% | 0 | 20 | 120 | 220 |
| 90% | 0 | 5 | 105 | 205 |
| 100% | 0 | **2** | **100** | **200** |

### 为什么不按次固定价

固定价 = `单价 × 次数`，是**线性支出**。而收入有每日额度（常数级），
两者幂次不匹配，导致喂得越勤越亏 —— 完整分析见
[04-balance.md](04-balance.md#收入与支出的幂次匹配)。

按量计价后，一天要补的饱食总量由周期决定（`24 / 周期`），
**与喂几次无关**，支出饱和成常数级，和收入对齐。

### 为什么附加效果反而要固定价

只有**饱食**该按量收 —— 它是被"补上多少"这个量纲衡量的。
附加效果没有这个量纲：小鱼干的 buff 是"24h 内达成率 ×1.6"，
宠物饿不饿都一样有用。

最初整个价格都乘倍率，后果是**饱食 99% 时小鱼干只要 3 枚却拿满额 buff**。
那立刻成为最优解：先喂饱粮（便宜），再补一口小鱼干白拿 buff。
"奢侈品"定位被自己的计价公式拆掉了。

现在罐头/小鱼干在满饱时仍要 100 / 200 枚，就是那份效果的定价。

### 为什么要有最低价

按量计价在饱食趋近 100% 时价格趋近 0。取整后，
**幼年 12h 周期下喂饱后 7 分钟内一切都免费**
（掉 1% 只需 `12h × 1% = 7.2 分钟`）。

免费本身不亏 —— 但 `foodCounts` 驱动着美食类成就，
零成本就能刷。所以普通粮设最低 2 枚。

剩饭是唯一豁免（`isFree`），它必须永久免费作防死锁的兜底（见下）。

### 副作用：「浪费」概念消失

半饱时吃罐头只补 50%，**饱食那部分**就只收 50% 的钱。所以随时喂都不亏，
`isWasteful()` 提示和 `food.wasteful` 本地化文案都删掉了。

注意不是整个价格减半：罐头空腹 150（饱食 50 + 心情 100），
半饱 125（饱食 25 + 心情 100）。

这比原来的橙色警告更好：不需要教育玩家「什么时候该吃什么」，
定价本身就是自解释的。

## 为什么有免费档

保证长期不登录的用户回来也能喂饭，不会掉进
「没钱 → 宠物一直饿 → 达成率低 → 更没钱」的死循环。

Dormans 在 *Machinations* 里把这类结构叫 **converter engine**，
并明确警告 deadlock 风险：两种资源同时枯竭，引擎就再也转不动。
他的建议正是配一个 **weak static engine** —— 剩饭就是这个角色。

参考猫咪后院的 Thrifty Bitz（免费但效果差的食物）。

## 为什么主粮要收钱

如果普通粮免费，硬币就没有必须花的地方，会无限累积失去意义。
这是设计里明确要避免的「钱多到没意义」。

## 「能管多久」的显示规则

```swift
func effectiveHours(currentSatiety: Double, stage: PetStage) -> Double {
    actualRestore(currentSatiety: currentSatiety) * stage.hungerCycleHours
}
```

两个要点：

**按当前饱食算，不用标称值。** 恢复是「加到当前值并封顶 100%」，
半饱时吃罐头只补一半，标称「能管 8 小时」会让人觉得被骗。

**周期随生命阶段变化。** 幼年 12h、成年 8h，所以同一份普通粮
在幼年能管 8.4 小时、成年只有 5.6 小时。必须传 `stage`。


## 不做背包

买了立即用。理由：
- 省掉一整套背包 UI（列表、数量、堆叠、丢弃）
- 宠物 app 的核心是照顾，不是资源管理
- 没有"囤货"就没有"什么时候用"的决策负担

代价是不能"批量买 10 份普通粮"，但每次喂食本来就要点开选择器，
多点一下不算负担。

## 不做食物变质

考虑过"食物会过期"这类设计，否决理由：
- 需要背包（见上）
- 增加负面情绪（打开发现食物坏了），而宠物 app 应该是放松的
- 猫咪后院、Pou 都没有这个设计

## 小鱼干的 buff

24 小时内**达成率 ×1.6**（不是乘最终收益）。

### 为什么不能是「乘收益」

试过，实测多赚 **+0**。额度制下任何乘 buff 都会被封顶吃掉：
收益本来就受 `min(剩余额度, ...)` 限制，乘再多也拿不到。

抬高达成率则不同 —— 它让每次结算领得更多，在额度用完前就生效：

| 次/天 | 普通 | 有 buff | 多赚 |
|---|---|---|---|
| 2 | 60 | 98 | **+38** |
| 3 | 123 | 198 | **+75** |
| 4 | 196 | 225 | +29 |
| 5 | 225 | 225 | +0 |

### 定位：帮没空的人追进度

在 2-4 次/天最有效，5 次以上归零（那些玩家本来就领满额度）。

这个定位比「给勤快的人叠加更多」更合理：它是**追赶机制**，
不是滚雪球。花 250 枚在 3 次/天时多赚 75，约 3 天回本 ——
配合心情 +25% 的间接收益，是一笔合理但不必然的投资。

buff 到期时间存在 `PetWallet.boostUntil`，而非 `PetState` ——
它是经济系统的一部分，换宠物不该清除。

## UI 形态

喂食按钮点开一个选择器（sheet 或 popover），四个横向卡片：

```
┌──────────┬──────────┬──────────┬──────────┐
│    🥣    │    🍚    │    🥫    │    🐟    │
│   剩饭    │  普通粮   │   罐头    │  小鱼干   │
│   免费    │   35 枚   │  150 枚   │  250 枚   │
│  约2小时  │  约6小时  │  约8小时  │  约8小时  │
│          │          │  心情+10% │ 心情+25%  │
│          │          │          │ 达成率×1.6│
└──────────┴──────────┴──────────┴──────────┘
```

价格是**动态的** —— 饱食部分按当前饱食度算，越饱越便宜；
附加效果部分固定。上表是空腹时的价格。

买不起的置灰但仍可点（点了提示「硬币不够」），不要直接隐藏 ——
让玩家看到目标才有攒钱动力。

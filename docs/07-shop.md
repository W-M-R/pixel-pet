# 开局与商店

## 开局流程

两步，不是一步：

1. **选宠物** —— 看属性对比（信息量大）
2. **起名** —— 专注输入

挤在一屏会让两件事都做不好。名字留空就用品种名，不强迫。

### 为什么要花钱买第一只

送 5000，首宠扣 4000，余 **1000** 起步。

直接送一只的话，开局的选择缺少代价 —— 玩家不会认真看属性差异。
花掉 80% 的启动资金去选，这个决定才有重量。

剩下 1000 枚够买 28 份普通粮（35/份）或 6 份罐头，
有「刚好够用但要省着花」的紧张感，又不至于卡死（剩饭永久免费）。

### 开局未完成时不结算

`PetHomeView` 里 `if !needsOnboarding { runOpening() }`。

否则新玩家还没选宠物就先收到一条「我帮你看家赚了 N 枚」，
而且会白白消耗掉首日签到。

所以 30 天总收入 = 余 1000 + 日常 + 成就 7050：

**成就占绝对主导** —— 低频和高频的 30 天总收入只差 35%，

## 属性差异的配平

### 三个维度，但只有两个真影响收益

| 维度 | 影响收益？ | 为什么 |
|---|---|---|
| 心情周期 | ✅ 是 | 心情占达成率 **60%** 权重 |
| 金币加成 | ✅ 是 | 直接乘在收益上 |
| 清洁周期 | ❌ **否** | 清洁不在达成率公式里 |

清洁被排除是早先的刻意设计（72h 周期让它长期接近 1.0，
放进公式只会稀释另两维，见 `RewardRule` 的注释）。

所以清洁周期只影响**洗澡频率**，是体验差异而非数值差异。
第一版我给 bird 配了「清洁劣势 + 金币优势」，结果它明显最优 ——
因为那个"劣势"是假的。

### 用金币加成抵消心情周期

反解让「成年 4 次/天」等于猫的基准（+96）的系数。
**用枚举而非二分**，理由见下一节：

```
13h → 1.08    16h → 1.03    19h → 0.99    22h → 0.96
14h → 1.06    17h → 1.01    20h → 0.98
15h → 1.04    18h → 1.00    21h → 0.97
```

跑 `python3 tools/econ_report.py` 可以重新生成这张表。

### ⚠️ 曾经踩过：二分求解 + 三位小数取整 = 掉档

第一版用手写二分（60 次迭代）解出三位小数，然后取整到两位。
**10 行里有 4 行错**：

| 心情 | 二分解 | 取整后 | 实际净结余 |
|---|---|---|---|
| 16h | 1.011 | 1.01 | **92** ❌ |
| 18h | 0.985 | 0.98 | **92** ❌ |
| 19h | 0.975 | 0.97 | **92** ❌ |
| 20h | 0.965 | 0.96 | **92** ❌ |

两个原因叠加：

1. **目标函数是分段常数函数**（含 `Int(x.rounded())`），数学上**没有根** ——
   它跳过目标值。所以 `scipy.brentq`（要求 `f must be continuous`）和
   `fsolve`（需要导数，这里梯度几乎处处为 0）都不适用。
2. **二分收敛到平台左边缘**，零余量。再减 `1e-6` 就掉下一档，
   取整到两位小数时很容易掉出去。

正解是**枚举两位小数网格**（候选只有约 40 个），取命中平台的**中点**：

```python
hits = [g for g in cands if net_for(stage, mood, g, feeds) == target]
return hits[len(hits) // 2]      # 中点 = 双向余量最大
```

见 `tools/econ_report.py` 的 `solve_gold()`。

### 最终配置

| 品种 | 性格 | 心情 | 清洁 | 金币 | 1次 | 2次 | 3次 | 4次 |
|---|---|---|---|---|---|---|---|---|
| 猫 | 均衡 | 18h | 72h | 1.00 | −8 | **+10** | +48 | +96 |
| 狗 | 黏人 | 14h | 72h | 1.10 | −8 | +8 | **+51** | **+104** |

**猫在低频（2 次/天）占优，狗在高频（3-4 次/天）占优。**

### ⚠️ 更严重的一坑：4 次/天「打平」是假象

狗的金币原本定 1.05，因为那个值让 4 次/天双方都是 +96。
但支配检验发现 **猫在全部四个阶段都支配狗**：

```
adult:  cat [-8, 10, 48, 96]
        dog [-9,  6, 45, 96]   ← 每个频次都不占优
```

根因：**1.05 是只对齐了 4 次/天一个点反解出来的**，
而那个点双方都撞额度上限、加成被 `min(remainingCap, ...)` 吃掉，
所以「持平」不是配平的结果，是封顶的结果。
低频时加成生效了，可心情劣势也生效，狗就纯亏。

提到 1.10 后差值变成 `1次 +0 / 2次 −2 / 3次 +3 / 4次 +8`，
各有胜负，支配关系消失。

**教训：配平不能只看一个工作点。** 现在由两个测试守着：
- `ConfigTests.testNoBreedDominatesAnother` —— 遍历四阶段 × 四频次
- `ConfigTests.testEveryBreedWinsSomewhere` —— 每个品种都要在某处占优

`tools/econ_report.py` 的第四节也会输出支配检验。

## 购买是一次性解锁

买过就永久拥有，之后**免费随时切换**。

不做成消耗品 —— 否则玩家不敢换，收藏的乐趣就没了。
`PetWallet.purchase` 是幂等的，重复买不重复扣钱。

### `choose` 要求已拥有

```swift
guard wallet.owns(breed) else { return false }
```

否则免费就能玩到所有宠物。设置页的品种选择器也只列已拥有的 ——
列出未购买的会让玩家点了没反应。

## 加新品种的步骤

1. `Assets/pets/<id>.png`（LPC 布局：16 列 × 8 行，32×32 格）
2. `python3 tools/make_stages.py --pets <id>` 生成阶段帧
3. `python3 tools/make_sleep.py` 生成睡姿帧
4. `PetBreed.all` 加一条，**注意**：
   - `footPadding` 要实测（逐行扫 alpha 找内容底边，见 `PetBreed` 注释）
   - `moodCycleHours` 与 `goldMultiplier` 按上面的配平表取
   - `price` 参考 10000 这个档
5. 本地化：`breed.<id>`、`trait.<x>`
6. 跑 `ConfigTests` —— 它会校验每个品种的参数是否合理

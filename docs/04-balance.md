## 收入与支出的幂次匹配

参数调不平的时候，先查幂次，别调数值。

分类学来自 [Daniel Cook, *Value chains*](https://lostgarden.home.blog/2021/12/12/value-chains/)（Lostgarden, 2021），
上位框架是 faucet-and-drain economy；原语（source / pool / converter / drain）
出自 Joris Dormans & Ernest Adams, *Game Mechanics: Advanced Game Design*。

| 项 | 类型 | 幂次 |
|---|---|---|
| 离线看家（旧：按小时 × 速率，10h 上限） | capped source | x⁰ |
| 喂食（旧：固定单价 × 次数） | **repeatable sink** | **x¹** |
| 离线看家（新：每日额度 × 达成率） | capped source | x⁰ |
| 喂食（新：按恢复量计价） | capped sink | x⁰ |

Cook 的规则是 *lower power sources feed into equal or higher power sinks*。
旧设计是**常数级收入配线性级支出** —— 喂得越勤支出越涨，收入却被上限压平，
必然「照顾越勤越亏」。他专门点了这个反模式：用 sink 的**量级**冒充 sink 的
**幂次**，长期一定被高幂次的一方压垮。

所以降粮价治不了：试过 35/40/45/50 四档，懒人结余始终最高。
必须让支出也变成常数级 —— 这就是「按恢复量计价」。

另一条相关的：Dormans 警告 converter engine 有 **deadlock** 风险
（两种资源同时枯竭就再也转不动），建议配一个 **weak static engine**。
免费无限的剩饭正是这个角色，防「没钱→宠物饿→达成率低→更没钱」死循环。

## 为什么支出会饱和成常数级

```
日粮钱 = Σ(每餐实际恢复量 × 10 × 5 × 倍率)      // 每餐单独取整

饱和后 ≈ (24 / 饱食周期) × 10 × 5
  幼年 100 / 成长 120 / 成年 150 / 老年 133

饱和门槛 = 24 / (0.70 × 周期)
  幼年 2.9 次 / 成长 3.4 次 / 成年 4.3 次 / 老年 3.8 次
```

一天需要补的饱食总量由周期决定，**与喂几次无关** —— 喂得勤则每次只补一点、
单次便宜。所以支出在目标节奏附近就饱和了。

⚠️ 门槛**之下**支出仍是线性的（宠物长时间挂在 0，那段亏空补不回来，所以花得少）。
但那个区间玩家本来就在亏钱，不影响结论。

⚠️ 逐餐取整带来 ±4% 偏差（周期除不尽 24 时更明显，如老年 9h）。
**测试断言必须留容差**，不能写死等于理论值。

## 攒钱节奏只由一个比值决定

```
攒一份小鱼干的天数 = 50×UNIT / (dailyCap − 24/周期×10×UNIT)
```

化简后只取决于 `dailyCap / UNIT`。当前成年是 45，对应 3.2 天。

这个性质很有用：**峰值净结余 = dailyCap − 日粮钱，与达成率无关**。
所以「攒钱快慢」和「状态影响多大」是两个独立旋钮，可以分开调。

## 硬约束

**每日额度必须大于该阶段的日粮钱**，否则那个阶段怎么玩都亏。
`EconomyTests.testDailyCapExceedsDailyFoodCost` 守这条。

第 8 版踩过：幼年额度 150、日粮钱 150（当时所有阶段共用 8h 周期），
新手前 3 天全线亏钱。这也是饱食周期改成按阶段区分的原因 ——
否则「阶段差异」和「收支平衡」被压在同一个旋钮上，调不开。

## 进食节奏

饱食周期按阶段变化，阈值不是 0：

| 阶段 | 周期 | 报「饿了」(0.4) | 「很饿」(0.15) | 实际节奏 |
|---|---|---|---|---|
| 幼年 | 12h | 7.2h | 10.2h | 约 3 次/天 |
| 成长 | 10h | 6.0h | 8.5h | 约 3.5 次/天 |
| 成年 | 8h | 4.8h | 6.8h | 约 4.3 次/天 |
| 老 | 9h | 5.4h | 7.7h | 约 3.8 次/天 |

**小宠物吃得少** —— 既有叙事合理性，也是让幼年期不亏钱的必要条件。

跨阶段那一刻饱食度会小幅下跳（周期变短了）。不做平滑：
一天只可能发生一次，且「长大了更容易饿」符合直觉。

## 达成率

```
达成率 = 0.05 + 0.30 × (0.40×饱食 + 0.60×心情)²        // 0.05 ~ 0.35
```

**用平方而非线性。** 线性只能拉开 2.2 倍差距，压不住支出增长；
平方后勤快照顾（0.30）与放养（0.08）差约 4 倍。

**上界 0.35 而非 1.0** 是刻意的：让一次结算领不满额度，
否则「开 1 次」和「开 5 次」收入相同，激励结构失效。
0.35 对应约 3 次结算才领满，正好落在目标节奏（4-5 次/天）之下。

**心情权重 0.60 > 饱食 0.40** —— 情绪价值是宠物 app 的核心。
心情从满到空，达成率降到约 30%。

**清洁不参与。** 72h 周期让它长期接近 1.0（离线 24h 时还有 0.83，
而饱食只剩 0.17），放进公式只会稀释另两维。
它仍是照料内容 —— 状态条、台词、洗澡成就都保留，只是不折算成钱。

## 收支平衡表

按「全吃普通粮、均匀分段」计算。收入走钱包累加，所以额度封顶真实生效。

### 成年期（周期 8h，额度 225）

| 次/天 | 收入 | 粮钱 | 结余 |
|---|---|---|---|
| 1 | 17 | 35 | **−18** |
| 2 | 60 | 70 | **−10** |
| 3 | 123 | 105 | +18 |
| 4 | 196 | 140 | +56 |
| **5** | 225 | 150 | **+75 ← 峰值** |
| 6 | 225 | 150 | +75 |
| 8 | 225 | 152 | +73 |
| 12 | 225 | 156 | +69 |

### 幼年期（周期 12h，额度 170）

| 次/天 | 收入 | 粮钱 | 结余 |
|---|---|---|---|
| 1 | 14 | 35 | −21 |
| 2 | 54 | 70 | −16 |
| 3 | 108 | 99 | +9 |
| 4 | 164 | 100 | +64 |
| **5** | 170 | 100 | **+70** |
| 12 | 170 | 96 | +74 |

三条性质：

1. **从放养到目标节奏严格递增** —— 这是「照顾好宠物=赚得多」的可执行版本，
   由 `testCareIncentiveIncreasesUpToTarget` 守着。
2. **超过目标节奏后平缓**（12 次/天仍有峰值的 92%）— 不惩罚热情玩家，
   也刷不到更多。
3. **放养会亏**（1-2 次/天倒亏 10-21）—— 不管宠物就该亏，这是设计意图。

额度制下净结余对喂食次数的导数**不可能全区间为正**：领满后再喂只增支出。
所以目标只到「峰值」为止，之后要求的是「不暴跌」。

### 只喂食不陪玩（心情钉在 0.15）

| 次/天 | 收入 | 粮钱 | 结余 |
|---|---|---|---|
| 3 | 51 | 105 | **−54** |
| 5 | 100 | 150 | **−50** |

心情占达成率 60% 权重，所以不陪玩会倒亏。这正是想要的：不能只喂饭。

### 攒钱奏

| 目标 | 满价 | 成年（+75/天） | 幼年（+70/天） |
|---|---|---|---|
| 罐头 | 150 | 1.9 天 | 2.0 天 |
| 小鱼干 | 250 | 3.2 天 | 3.4 天 |

四档节奏一致（3.2-3.4 天），因为额度和周期是配套调的。

### 小鱼干 buff（达成率 ×1.6，成年）

| 次/天 | 普通 | 有 buff | 多赚 |
|---|---|---|---|
| 2 | 60 | 98 | **+38** |
| 3 | 123 | 198 | **+75** |
| 4 | 196 | 225 | +29 |
| 5 | 225 | 225 | +0 |

它帮「没空频繁开」的玩家追进度，开得很勤的人本来就领满、无额外收益。
这个定位比「勤快的人叠加更多」更合理。


## 调参过程

记录下来是因为**中间几版都有明显问题**，避免以后又改回去。

### 第 1 版：普通粮免费

```
看家 2 枚/h，上限 12h，普通粮 0 枚
→ 日收益 46 枚，必要支出 0
```

**问题**：硬币没有必须花的地方，会无限累积失去意义。
这是设计里明确要避免的"钱多到没意义"。

### 第 2 版：普通粮 5 枚

```
看家 2 枚/h，上限 12h，上线 +3
→ 4 次/天：收 54，支 20，结余 +34
```

**问题**：结余太多，等于普通粮的价格形同虚设。

### 第 3 版：发现"不奖励勤快"

用"离开那一刻的状态"算系数时：

```
4 次/天：结余 +34
2 次/天：结余 +34      ← 一样！
```

**问题**：开得越勤，每次离线越短，总收益反而没优势——
等于**惩罚勤快的玩家**，和"照顾好宠物"的初衷相反。

**解法**：系数改用**离线期间的平均状态**。
一天 2 次意味着宠物有 4 小时饿着，平均状态低 → 系数低 → 收益降。

### 第 4 版：降速率 + 提价

```
看家 1.0 枚/h（原 2.0），上限 10h（原 12），
上线 +1（原 3），普通粮 7 枚（原 5）
→ 结余全部落在 ±5 枚
```

**问题**：系数只看饱食，心情和清洁再差也不扣钱。

### 第 5 版：三维乘法 + 微调速率

改成三维压缩乘法后，系数整体上移（清洁周期长，长期接近 1.0），
结余涨到 +6~11，于是把速率从 1.0 降到 0.9、系数区间从
`0.4+f×1.1` 收到 `0.3+f×1.05`：

```
看家 0.9 枚/h，上限 10h，上线 +1，普通粮 7 枚
状态系数 = 0.3 + (三维压缩乘积) × 1.05    // 0.58 ~ 1.35
→ 结余 +0.5 ~ +5.6，且心情差会明显扣钱
```

**问题**：数值量级太小。日收入只有 20-30 枚，一份粮 7 枚，
玩家一天只够买 3-4 份。「7 枚一份粮」这个数字本身也不好记，
而且个位数货币让成就奖励（10~300 枚）显得虚高。

### 第 6 版：整体放大 10 倍

参考猫咪后院、Pou 等产品——货币面额都不是个位数。
所有数值 ×10，比例关系完全不变：

```
看家 9 枚/h，上限 10h，上线 +10
食物 0 / 70 / 140 / 320
成就 19 条共 13350 枚（原 1335）
启动资金 100 枚（原 0）
```

顺带修了启动资金：原本是 0，新玩家第一顿只能吃剩饭（30% 饱食），
第一印象是「穷」。给 100 枚够买一份普通粮，让第一次喂食就有得选。

### 第 7 版：每日额度制（推翻按小时累积）

固定单价 × 次数是线性支出，配 10h 上限的收入必然「越勤越亏」。
改成额度制，并按生命阶段区分额度：

```
收益 = min(今日剩余额度, 额度 × 达成率 × buff)
额度 = 幼280 / 成长340 / 成年420 / 老年350
达成率 = 0.10 + 0.90 × blend²        // 0.10~1.00
单次领取上限 = 额度 × 20%
食物按恢复量计价，每 10% = 5 枚
```

**问题一：单次上限盖住了达成率。**

实测任何正常状态下都是单次上限在起作用 —— 达成率要低于 0.15 才接管，
那对应饱食心情**都接近 0** 的极端情况。

铁证：三组完全不同的达成率区间（0.10~1.00 / 0.35~0.75 / 0.30~0.85）
跑出来的日收支表**一模一样**。「照顾好宠物=赚得多」被彻底架空。

**问题二：额度 420 太高。** 峰值 +270/天，小鱼干（250）不到一天就买得起。
上一版是 53 天 —— 从一个极端荡到另一个极端。

**问题三：小鱼干的乘法 buff 被封顶吃掉。** 抬高额度 +30% 实测多赚 **+0**，
因为单次上限限住了，5 次/天根本领不到抬高后的额度。

### 第 8 版：去掉单次上限

达成率成为唯一的状态旋钮，立刻生效（0.08 → 0.30 随状态变化）。

同时发现一个好性质：**峰值净结余 = 额度 − 日粮钱，与达成率无关**。
于是「攒钱节奏」和「状态影响多大」解耦成两个独立旋钮。

**残留问题：幼年期全线亏钱。** 当时所有阶段共用 8h 周期，
日粮钱恒为 150，而幼年额度只有 150 —— 达成率 <1 时必亏，新手前 3 天卡死。

试图靠调额度解决时撞上死结：

```
幼年不亏      → young_cap > 30·UNIT
成年攒钱3-4天 → adult_cap ≈ 44·UNIT
推出            adult/young < 1.47
```

想要的阶段梯度勉强能塞进去，但幼年只能「刚好不亏」，没有结余空间。
根因是**把「阶段差异」和「收支平衡」压在同一个旋钮上**。

### 第 9 版（最终）：饱食周期也按阶段区分

让小宠物吃得少，支出跟着阶段降，两个旋钮就分开了：

```
周期   幼12h / 成长10h / 成年8h / 老9h
日粮钱 幼100 / 成长120 / 成年150 / 老133
额度   幼170 / 成长195 / 成年225 / 老205
达成率 0.05 + 0.30 × blend²          // 0.05~0.35，上界刻意压低
小鱼干 达成率 ×1.6（不是乘收益）
无单次上限
```

达成率上界从 1.00 压到 0.35，是为了让一次结算领不满额度 ——
这样「多开一次」始终有收益，而不需要单次上限那种会遮蔽状态的机制。

小鱼干改成抬高**达成率**后，在 2-4 次/天立刻生效（多赚 +29~75）。

四档的攒钱节奏收敛到 3.2-3.4 天，幼年最差 +9（3 次/天）不再卡死。

调参过程的教训：**第 7、8 两版都在调数值，但问题是结构性的。**
先按 Cook 的幂次分类查清 source/sink 类型，能省掉这两轮。

## 平均状态的推导

三条线都是线性衰减，所以平均值用梯形法就是精确解：

```
若 离线时长 ≤ 周期:
    平均 = (1.0 + (1 - 离线/周期)) / 2 = 1 - 离线/(2×周期)
若 离线时长 > 周期:
    平均 = (周期 × 0.5) / 离线时长        ← 衰减到 0 后就一直是 0
```

各阶段的饱食平均值（心情固定 18h 周期）：

| 离线 | 幼(12h) | 成年(8h) | 心情(18h) | 成年达成率 |
|---|---|---|---|---|
| 2h | 0.92 | 0.88 | 0.94 | 0.30 |
| 4.8h | 0.80 | 0.70 | 0.87 | 0.24 |
| 6h | 0.75 | 0.62 | 0.83 | 0.22 |
| 8h | 0.67 | 0.50 | 0.78 | 0.19 |
| 12h | 0.50 | 0.33 | 0.67 | 0.15 |
| 24h | 0.25 | 0.17 | 0.38 | 0.08 |

达成率随离线拉长单调下降，所以「长时间不管」自然少赚，
不需要额外的惩罚规则。

## 成就的作用

成就总量 13350 枚 ≈ **178 天**日常结余（按成年 +75/天）。

上一版这个比值是 2225 天（成就占总收入 95%），意味着日常收入形同虚设。
现在成就仍是长期激励，但日常收入本身站得住了。

分布上前期密集（首次喂食 100、连续 3 天 200），后期稀疏但金额大
（相伴 100 天 3000），符合「新手期给正反馈、长期给目标」的常规节奏。

## 需要实测验证的

文档里的数字都是算出来的，以下需要真实体验后调整：

- **成年 4.3 次/天是否太频繁**。如果实测觉得「缠人」，
  把 `PetStage.hungerCycleHours` 的成年档从 8h 放宽到 10h。
- **额度封顶是否可感知**。领满后再开就没有看家收益了，
  目前没有任何 UI 提示。玩家可能困惑「怎么这次没赚钱」。
  这是当前最可能需要补的体验缺口。
- **攒钱 3.2 天是否合适**。要调就改 `dailyCap`，
  它是唯一能整体缩放收入而不影响状态曲线的旋钮
  （因为峰值 = 额度 − 日粮钱，与达成率无关）。
- **达成率上界 0.35 是否太低**。它决定「几次结算能领满额度」，
  调高会让少开几次的玩家更快领满，削弱勤快的优势。

若要单独调整「心情有多重要」，改 `Rate.moodWeight`（现在 0.60），
并把 `satietyWeight` 相应调整使两者和为 1.0。

⚠️ 改任何数值都会让 `Tests/EconomyTests.swift` 的平衡回归失败 ——
那是提醒回来更新本文档，不是让你改断言。

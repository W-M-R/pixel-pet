## 设计原则

这五条约束决定了所有设计取舍，改设计前先确认没有违背它们。

**1. 完全离线，无服务器**
没有账号、没有云同步、没有广告 SDK。所有状态存本地 JSON。

**2. 时间戳驱动，不用后台定时器**
iOS 不给第三方 app 后台定时器。所以状态一律按 `now - lastXxxAt` 实时计算，
绝不存"当前饥饿值"这类快照——app 一进后台快照就停了，用户回来会看到假数据。

这条约束反而让"离线收益"变得自然：算收益和算状态是同一套逻辑。

**3. 无额外美术产能**
宠物用 LPC 免费素材（cat/dog 各 4 毛色），四个生命阶段是程序化派生的。
界面与食物图标由脚本生成（`tools/make_ui_icons.py`），装饰用手绘像素块。
**任何需要成套新美术的设计都不可行**，评审时要先问"这需要画多少张图"。

**4. 目前不做内购**
经济系统的目的是**留存**，不是变现。
参考猫咪后院：它的经济循环撑起了国民级留存，内购只是去广告。

**5. 照顾好宠物 = 赚得多**
这是核心正循环。收益 = **每日额度 × 达成率**，达成率由离线期间的
平均饱食与心情决定，所以「摆烂」会自动惩罚，不需要额外规则。

**心情权重 0.60 > 饱食 0.40** —— 心情是宠物 app 的情绪核心，
不该只靠喂饭就能拿满收益。清洁不参与收益（周期 72h，长期接近 1.0，
放进公式只会稀释另两维），但仍是照料内容。

这条约束的可执行版本是「从放养到目标节奏，净结余严格递增」，
由 `EconomyTests.testCareIncentiveIncreasesUpToTarget` 守着。
实施时踩过两次坑（固定单价导致越勤越亏、单次上限遮蔽达成率），
详见 [04-balance.md](04-balance.md) 的调参记录。

## 反面教材

设计时明确避开的：

- **双货币**：`My Tamagotchi Forever` 有 Coins + Gems，玩家评价
  "Gems, the more expensive of the two, are almost worthless"。一种货币够了。
- **免费主粮**：如果基础食物免费，硬币就没有必须花的地方，会越攒越多失去意义。
- **无保底**：如果所有食物都要钱，长期不登录的用户回来可能没钱喂饭，卡死。
  所以有"剩饭"这一档：免费无限，但只恢复 30%。

## 落地位置

这份设计的每一项都已实施，对应代码如下：

| 项 | 落在哪 |
|---|---|
| 饱食周期 8 小时（成年） | `PetState.Decay.hunger`；其余阶段走 `PetStage.hungerCycleHours`（幼年 12h / 成长 10h / 老年 9h） |
| 硬币与每日额度 | `PetWallet`（额度 `stage.dailyCap`），收支收口在 `CoinLedger` |
| 食物四档 | `FoodItem.all` = 剩饭 / 猫粮 / 罐头 / 小鱼干，定价见 `minPrice` 与 `isFree` |
| 奖励系统 | `RewardRule` 协议 + `RewardEngine`，29 条成就在 `RewardRules`（6 组） |
| 界面图标 | 全部手绘像素图（`PixelIcon` + `tools/make_ui_icons.py`），**不用 emoji 也不用 SF Symbols** |

最后一项与原计划不同，值得记一下：当初只打算修 emoji 的
`Text(verbatim:)` bug（根因见 [05-implementation.md](05-implementation.md#已修复的-bug留档)），
后来改成整套自绘。两个理由：emoji 是高分辨率渐变图，紧挨着 4 倍放大的像素精灵会把
像素质感压平；且它的字形随 iOS 版本变。`ConfigTests` 里有一条测试直接禁用
`systemName:` / `systemImage:` —— 缺失的 symbol 会渲染成豆腐块，在像素风 app 里
是最刺眼的破相。

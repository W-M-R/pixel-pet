## 设计原则

这五条约束决定了所有设计取舍，改设计前先确认没有违背它们。

**1. 完全离线，无服务器**
没有账号、没有云同步、没有广告 SDK。所有状态存本地 JSON。

**2. 时间戳驱动，不用后台定时器**
iOS 不给第三方 app 后台定时器。所以状态一律按 `now - lastXxxAt` 实时计算，
绝不存"当前饥饿值"这类快照——app 一进后台快照就停了，用户回来会看到假数据。

这条约束反而让"离线收益"变得自然：算收益和算状态是同一套逻辑。

**3. 无额外美术产能**
宠物用 LPC 免费素材（cat/dog 各 4 毛色），四个生命阶段是程序化派生的。
食物图标用 emoji，装饰用手绘像素块。
**任何需要成套新美术的设计都不可行**，评审时要先问"这需要画多少张图"。

**4. 目前不做内购**
经济系统的目的是**留存**，不是变现。
参考猫咪后院：它的经济循环撑起了国民级留存，内购只是去广告。

**5. 照顾好宠物 = 赚得多**
这是核心正循环。收益系数由**离线期间三维状态的乘积**决定
（饱食 / 心情 / 清洁），所以"摆烂"会自动惩罚，不需要额外规则。

三维权重刻意不等：**心情最重**（满→空收益降 42%）、饱食中等、清洁最轻。
心情是宠物 app 的情绪核心，不该只靠喂饭就能拿满收益。

## 反面教材

设计时明确避开的：

- **双货币**：`My Tamagotchi Forever` 有 Coins + Gems，玩家评价
  "Gems, the more expensive of the two, are almost worthless"。一种货币够了。
- **免费主粮**：如果基础食物免费，硬币就没有必须花的地方，会越攒越多失去意义。
- **无保底**：如果所有食物都要钱，长期不登录的用户回来可能没钱喂饭，卡死。
  所以有"剩饭"这一档：免费无限，但只恢复 30%。

## 与现状的差异

实施时需要改动的地方：

| 项 | 当前代码 | 设计目标 |
|---|---|---|
| 饱食周期 | 12 小时 | **8 小时** |
| 硬币 | 无 | 新增 `PetWallet` |
| 食物 | 单一"喂食"按钮，无消耗 | 四档，需选择与花钱 |
| 奖励 | 无 | `RewardEngine` + 19 条成就 |
| emoji 图标 | **有 bug，按钮上不显示** | 修 `Text(verbatim:)` |

emoji bug 的根因见 [05-implementation.md](05-implementation.md#已知-bug)。
